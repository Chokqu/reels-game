# 03 — Authoritative game engine

## Session model

Use plain objects and Map/Set, not ORM or classes unless genuinely simpler. One active session (including final leaderboard until closed). Generate UUID v4 on server using crypto.randomUUID. A session is not a user login.

```js
session = {
  id, phase, createdAt, revision,
  playlist: [{ id, name, size, lastModified, duration }],
  currentIndex: -1,
  round: null,
  results: [],
  eligibleConnections: new Map(), // token -> Set(socketId)
  updatedAt
}
round = {
  id, videoId, index, startedAt, endsAt: null,
  votes: new Map(), // anonymous token -> integer score
  status: 'playing',
  timer: null
}
result = {
  roundId, videoId, index, status, // 'completed' or 'skipped'
  average, voteCount, distribution, completedAt
}
```

Playlist IDs generated by admin using crypto.randomUUID, unique within session, immutable once session created. No raw media or thumbnails in server state. `phase` values LOBBY, PLAYING, VOTING, RESULTS, LEADERBOARD. No active session means closed. REPLAY is local UI state, not server phase. Revisions monotonic within session; increase on visible state changes, including count changes. Connected count = number of unique participant tokens with at least one live socket in this session. Admin sockets are excluded. Vote count includes votes from people who have since disconnected; it can exceed connected count. Display separate counts, not misleading percentage. Optional progress meter only when denominator meaningful; avoid pretending it is attendance.

## Transition table

| Current | Trigger | Next | Guard/action |
|---|---|---|---|
| None | session:create | LOBBY | Auth, nonempty valid playlist, new UUID |
| LOBBY | video:start | PLAYING | Start first playlist item, new round UUID |
| PLAYING | video:ended | VOTING | Matching roundId, first valid event only, deadline now+15000 |
| PLAYING | video:skip | RESULTS | Matching roundId, terminal skipped result, no votes |
| VOTING | vote:submit | VOTING | Same round, integer 1–10, before deadline, new token |
| VOTING | vote:extend | VOTING | Admin, matching round, before deadline, +5000 |
| VOTING | vote:close or deadline | RESULTS | Freeze exactly once, clear timer, aggregate, persist |
| RESULTS | video:start | PLAYING | Next index exists; create new round |
| RESULTS | session:finish | LEADERBOARD | Normal after last item, explicit early finish allowed |
| LOBBY | session:finish | LEADERBOARD | Explicit early finish; empty results message |
| LEADERBOARD | session:close | None | Persist final, invalidate ID, notify sockets |
| Any | local replay | Unchanged | Never send video:ended for replay |

Unauthorized or invalid transitions reject without modifying any state. No direct jump from VOTING to PLAYING or finish: close round first. `video:start` derives next index from server; client cannot choose arbitrary index after session created. Session creation while one exists returns SESSION_ACTIVE; allow operator to resume. `video:skip` only for playback failure or explicit skip, requires confirmation; skip a playing round only. No automatic progression to next video.

## Deadline design

On first valid ended event: `endsAt = Date.now() + 15000`. Schedule one timeout using remaining milliseconds. Timeout callback captures session ID, round ID and expected deadline; if any mismatch, exit; if early, reschedule. Before vote, extend or close, check actual server wall clock against endsAt; if expired, finalize immediately then reject late command as appropriate. Extend only if still open, update deadline and clear/reschedule timer. Clear timers on finish, skip or close. The transition to RESULTS must be synchronous before async backup; protect against repeated timer/close events by phase and ID. Do not put an await between validation and Map insertion or state mutation.

Client countdown is cosmetic; snapshot includes serverNow and endsAt, compute offset and render remaining using ceil(max(0, endsAt - adjustedNow)/1000). Local 0 disables vote buttons and shows waiting for server. Never let client decide acceptance. Server receives scores before deadline; network delay is not compensated. Use no per-second server broadcasts: clients update clock locally and receive deadline changes.

## Votes and results

Validate session membership, role participant, round ID and integer score 1..10. Identity bound to anonymous token at join, not arbitrary vote payload. Token is random UUID generated in browser and saved per session in localStorage; fallback in-memory token if storage unavailable, with weaker refresh protection. Treat repeated request from same token as already accepted without adding a second score; return ALREADY_VOTED and snapshot voted flag. Do not overwrite initial score. Late stale-round votes never enter a new round. No IP identity and no fingerprinting. This protects accidental duplicate votes, not adversarial multiple browsers.

Aggregate once on close. Histogram always ten entries in numeric score order. `average = sum / count` without rounding internally; if count=0, average=null and histogram zeros. Show two decimals using Turkish locale if desired; sorting uses full precision. Tie-break by voteCount descending then original index ascending. Skipped results average=null, voteCount=0, distribution all zeros, status skipped. Completed zero-vote and skipped videos unranked at bottom, labeled separately. Unplayed excluded. Do not emit raw per-token scores, individual vote history or live distribution.

## Backup format

`data/results/<session UUID>.json` contains version 1, sessionId, createdAt, updatedAt, finalized flag, playlist metadata (ID, name, index; no token), completed results and ordered leaderboard. Write after close/skip of each round and finish/close. Serialize writes in a single promise chain, capture immutable data at enqueue time, write temporary file then rename atomically. Ensure directory exists. Never write admin cookie, anonymous tokens, raw votes or video content. Export from current server state or saved results by authorized route; validate UUID before resolving path. Backup warning is admin-only. No live restore on server restart; README must explicitly say so.
